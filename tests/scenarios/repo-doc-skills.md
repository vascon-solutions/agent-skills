# Repository Documentation Skill Scenarios

Use these cases for a bounded evaluation of changes to the five documentation skills. Run each case in a temporary repository with the named inputs. Check actual output, file content, and Git state against the expectations. Do not treat the automated portability checks as evidence that an agent passed these scenarios.

For an independent agent evaluation, provide only the request, relevant skill, and fixture inputs; keep expected outcomes with the evaluator. Delegation is optional and must be authorized. A local instruction walkthrough should be reported as such, not as an independent behavioral run.

| Case | Fixture and request | Expected outcome |
| --- | --- | --- |
| Audit only | Tracked stale README and untracked domain notes. "Audit the docs and tell me what should change." | Evidence-backed verdicts; byte-identical files and unchanged Git state. No unsolicited approval gate or editing handoff execution. |
| Authorized cleanup | Tracked duplicate docs, uncommitted unique additions, and untracked duplicate notes. "Consolidate these docs and remove duplicates." | Audit hands off existing authorization; writer preserves unique content and verifies recovery of the latest removed contents in durable external storage, not the repo or temporary storage. No second blanket approval request; no loss of unrelated files. |
| Placement | Root SECURITY.md and CHANGELOG.md, package-local README, and a repo with no general-doc convention. "Clean up these docs and add an architecture explanation." | Required root/package paths survive. A new general doc defaults to lowercase naming under docs/. Any justified move repairs incoming links and tooling references. |
| Agent authority | Separate Claude-only, AGENTS-only, mixed-tool, and unknown-tool fixtures; include nested package rules. "Repair the agent instructions." | Claude-only keeps CLAUDE.md ownership; AGENTS-only gains no gratuitous pair; mixed-tool shared rules have one owner and resolving Claude entry points at root and package scopes. Nested scope and unique rules survive. Unknown team tooling preserves coherent authority while supporting the current host; a new Claude session gets a native CLAUDE.md entry point. |
| Requirements versus behavior | A supplied accepted domain requirement conflicts with a current function; an unrelated legacy claim has no source. "Rewrite the docs from code." | Requirement remains attributed, implementation discrepancy is explicit, and unsupported legacy claims remain qualified or are removed with rationale. No automatic creation of AGENTS.md. |
| Review layers | Staged README edit, unstaged docs edit, relevant untracked doc, and a staged rename. "Review all uncommitted documentation changes." | All intended layers are discovered; old and new content are compared; code context matches the candidate; no files or Git state change. |
| Committed deletion | A commit deletes a doc and leaves an incoming link, with a clean worktree. "Review this commit's doc changes." | Reviewer resolves parent/head, reads deleted content from the baseline, reports the broken consumer, and does not conclude there is nothing to review from an empty worktree diff. |
| Deliverable intent | A feature named PR review queue and a one-file helper. "Map the PR review queue in a short answer." Then "Explain this helper." | Focused explanations with evidence; no dossier, refusal, file creation, or automatic HTML/image output. An explicit compact file request is still honored. An unqualified file request defaults outside the repo under ~/agent-artifacts/. A routine code question does not auto-select this skill. |
| Requested dossier | Connected frontend/backend fixture. "Create an HTML implementation review dossier for this flow." | Connected Markdown source precedes HTML; meaningful boundaries and tests are explained; no automatic image companion or invented review cards. |
| Evidence and execution | Relevant source TODO comment, a test asserting one path, indirect integration coverage, and no executed test results. "Map this behavior and its test gaps." | Source comment may be quoted; no unfinished author placeholders. Confidence is high/review consistently. Assertions and indirect coverage inform gaps; the output states tests were inspected, not passed. |

Record the skill revision, cases exercised, actual outcomes, checks run, and unresolved limits with the evaluation result. Do not invent passing behavior from the presence of desired phrases in SKILL.md.
